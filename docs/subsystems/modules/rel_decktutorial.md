## Pack 00: script interpreter, overlays, resource loader

- Opcode table `0x2156c`: entry n is the handler of opcode n, in address order `0x1bb4` (0x01) ... `0x27f0` (0x17). Entry 0 is a null pointer: Ghidra shows the null check in `deck_tutorial_run_script` and `deck_tutorial_op_allow_buttons` as a comparison with `deck_tutorial_draw`, because that export sits at module offset 0.
- Interpreter globals (all in the module's .bss): `0x22c30` script number (formats `deck_tutorial%02d.bin`), `0x22c32` scene state (0 and 4 draw nothing, `end` sets 3), `0x22c34` frame counter of the current wait, `0x22c3c` bit 0 = overlays visible (cleared while L is held), `0x22c3d` wait state (0 run, 1 message, 4 panel, 9 demo press, 10 wait, 15 menu step, 16 shoulder hint), `0x22c3e` flags (0x1 label, 0x2 highlight, 0x4 allowed buttons, 0x8 repeat, 0x10 shoulder hint shown, 0x20 no confirm swap, 0x40 picture), `0x22c40` program counter, `0x22c44` loop start, `0x22c48`/`0x22c4c`/`0x22c50`/`0x22c54` masked pad words (held, pressed, released?, repeat; the third is only copied), `0x22c70`/`0x22c72` wait kind and count, `0x22c74` demo mode, `0x22c76` demo step, `0x22c78` press step, `0x22c7c` demo mask, `0x22c80` highlight region, `0x22c82` repeat count, `0x22c84` allowed mask, `0x22c88` shoulder mask, `0x22c8c` menu item mask, `0x22c90` menu replacement string, `0x22c92` bit 0 message shown, bit 1 panel shown.
- Windows (0x120-byte list-window objects of BOOT.BIN `ui_open_list_window`): `0x22c94` label, `0x22db4` panel, `0x22ed4` picture, `0x22ff8` quit dialog (strTbl string 3). Window list `0x224fc`; heap pointer `0x22548`. The picture windows show command items (icon + string) from the 6-byte records at `0x215cc`-`0x215f1`, not bare strings.
- Resource table `0x21690`: 9 entries of 12 bytes (u32 id, cached member pointer, name format pointer), sorted by id at start-up and binary-searched (`0x3518`). Ids seen so far: `0x1010`, `0x1011` (message-window frame graphics), `0x1012` (button icon sheet), `0x1013` (panel backdrop), `0x1014`-`0x1016` (panel pictures of styles 1-3), `0x1040` (strTbl), `0x1041` (script). The archive is `deck/tutorial.ehp` loaded from root 3 into a heap buffer `0x220b4`; loader state byte `0x220b0` (bit 0 idle, bits 1-7 count of completed loads).
- Sample deck table `0x212ac`: 0x75 entries of 6 bytes: `u16 script mask` (bit n = used by script n), `u16 card id`, `u8 count` (bits 0-6), `u8 list` (0-3: which of the four editor list objects at `0x220c0 + 0x20 * n`). This is the card set the tutorial's editor shows; the port's extractor needs it (it is module data, not a file; the module has one load segment at file offset 0x54, so the table is at file offset `0x21300`). `deck_tutorial_init_session(script)` receives the u16 `0x22c30` (`lhu a0, 0x2c30(v0)` in the delay slot of the call at `0x377c`) and passes it to `deck_tutorial_init_sample_deck`, so the mask bit is the script number (high).
- Highlight geometry table `0x211fc`: 8-byte entries (u16 vertex count, pointer at +4 to 12-byte through-mode vertices, colour + x/y/z shorts, vertex type 0x80011c) indexed by region; for regions 0-3 the first quad is patched with the current tab rectangle.

## Corrections to docs/formats/deck.md

- Opcode 0x09 (`wait_button`) does not wait for the player: wait state 9 never reads the pad. `deck_tutorial_simulate_press` waits 9 frames, injects the button mask into the masked input words the editor reads (`0x22c48` held, `0x22c4c` pressed, `0x22c54` repeat) for one frame, then waits 18 more frames. It is a demonstration press ("the tutorial presses the button for you"); the icons drawn by `deck_tutorial_draw_demo_buttons` light up during the press. Mode 1 is a two-press demonstration that checks whether the card under the cursor is a fusion card (down, or confirm then confirm). Name suggestion: `demo_press`.
- Holding L hides the message, label, panel and picture overlays (bit 0 of `0x22c3c`), and message windows cannot be closed while they are hidden.
- A forever `repeat` (count 0) ends when confirm or cancel (0x6000) is pressed, not only through `repeat_end`.
- Opcode 0x17 calls `system_start_fade_out(1, 0xff000000, 16)` (the stub the doc calls `0x08844ec0`).

## Packs 01-03: entry points, shutdown, editor copy

- Exports (libdeck_tutorial_rel): `deck_tutorial_draw` (+0x0), `deck_tutorial_start` (+0x3598), `deck_tutorial_update` (+0x3718). `deck_tutorial_start(script, heap_args)`: script number to `0x22c30`; heap_args = optional `{parent heap, value stored at 0x22550}`. Without a parent heap the module creates its own 0x5c0000-byte (5.75 MiB) FPL; otherwise it takes that much from the caller's heap.
- Scene states `0x22c32`: 0 load (archive, then `0x1110c`), 1 fade-in, 2 run (script + editor; START opens the quit dialog, result 2 quits), 3 fade-out, 4 shutdown (`deck_tutorial_shutdown`, steps `0x221c2` 0-3). `deck_tutorial_update` returns 1 when finished.
- Save isolation: on start the module saves and clears the save's card byte-1 flag for card ids 0xe88-0x1f39 (backup array at `0x22290 + id`, i.e. `0x23118`-`0x241c9`) and the trunk display option (save setting byte 0xb0 bits 6-7, backup `0x241ca`); `deck_tutorial_shutdown` restores both. The tutorial editor can toggle these flags (command menu item 1, hold-R cancel, trunk option menu) without changing the player's save. The text-search history is a module buffer (`0x222a0`, 8 x 0x40 bytes) instead of the save's edit block.
- The editor is a copy of rel_deck's: list objects `0x220c0 + 0x20 * n` (n 0-5; count +8, entries +4, view +0x10, view count +0x14, view mode +0x16), trunk object `0x22120`, pane records `0x225a0` and `0x225cc` (0x2c bytes), layout byte `0x22560` (low nibble layout 0-7, bits 4-5 active pane, bits 7-14 a sub-screen state that diverts the editor to `0x10f08`), command menu record `0x241d4` (0x18 bytes), filter record `0x241ec` (0x18 bytes), editor mode `0x221c0` (0/6/7 browse, 1 card move, 2 command menu, 3 sort, 4 filter, 5 text search), undo stack `0x224a0`/`0x224a2`, search state `0x241d8`. Copies whose code differs from rel_deck (and so got `deck_tutorial_` names) add the tutorial hooks: menu windows take their input from the masked tutorial input `0x22c48` (window +0x11c) and call `deck_tutorial_apply_menu_step` while a `menu_step` is pending (wait state 15). The exception is the sort menu's direction window: it has no +0x11c, so by the `ui_update_list_window` rule it reads `system_pad_get_state()` directly (static reading, not traced). `deck_tutorial_apply_menu_step` runs when the next menu is built, before the window is finished or opened, not when the player chooses: it writes the disabled-item mask +0xdc. `deck_tutorial_cycle_pane_list` skips lists 4 and 5 in the single-pane layouts; in two-pane layouts pane 1 can never show list 5 (whoever owns the deck). List 4 (`0x22140`) is the alias of the side list: main and extra test the fullness of the side target on list 4's total `0x2214c`, trunk and pool on list 2's total `0x2210c`. Bit 0 of `0x2256c` locks the shown card; `deck_tutorial_op_show_card`, `deck_tutorial_start_card_move` and `deck_tutorial_open_sort_menu` all set it, so it is not a script-only flag.
- Filter table `0x219bc`: 8-byte records {u16 first value, u16 last value, u32 draw callback} indexed by filter number, the callback called as (list, x, y, value) with its result kept as the list: 1 {0, 6, `0x1a0c4`}, 2 {1, 0x15, `0x19f80`}, 3 {1, 6, `0x1a058`}, 4 {0, 2, `0x99d8` `deck_tutorial_draw_icon_17px`}, 5 {1, 9, `0x9ab0`}, 6 {0, 3, `0x1a19c`}, 7 {0, 0x26, `0x9bb4`}.
- Scripted filter check: in `deck_tutorial_handle_filter_value_window`, while `allow_buttons` is active the OK row is accepted only when the chosen value bitmask equals `~(window +0xdc)`, the mask that `menu_step` stored. The scripts therefore force the exact filter selection they describe.

## Packs 04-06: card moves, editor loading, messages, sort

- Wait kinds 3 and 4 of opcode 0x0a are driven by the editor: `deck_tutorial_start_card_move` increments the wait counter `0x22c34` when a card move starts (kind 3, the move window opens), `deck_tutorial_finish_card_move` when a card lands in its target list (kind 4). The script `wait 3/4, n` therefore waits for the player to start or complete n card moves. This answers the "advanced elsewhere" note in docs/formats/deck.md (high).
- Loading: `deck_tutorial_poll_load` first loads `deck/tutorial.ehp` (own resource table `0x21690`, 9 entries), then `deck_tutorial_poll_editor_load` loads the deck editor's archive `deck/all_<l>.ehp` (copy of rel_deck's resource system: table `0x21d2c`, 41 records, state `0x24b20`, archive pointer `0x22550`) and opens the card-image reader `card_db_open_cardh_cip` in a 0xd1000-byte buffer (`0x2255c`, handle `0x2254c`). `deck_tutorial_start`'s second argument word (heap_args[1]) goes to `0x22550`, so a caller that already holds `deck/all_<l>.ehp` (rel_deck) can pass it in and the module skips that load (medium: inferred from the shared global).
- Move record `0x241f0` (0x250 bytes, as in rel_deck): byte 0 low nibble state (1 fly-in, 2 window opening, 3 input, 4 cancel, 5/6 closing, 7 fly-out, 8 done), high nibble sub-step; +2 entry index, +4 view position; byte 6 source pane (bits 0-1), source list (bits 2-4), target pane (bits 5-6); u16 +6 bits 7-9 target count; targets u16 +8.., full flags u16 +0xe..; +0x14 list shown in the target pane; +0x1c/+0x20/+0x24 label x/y/width; +0x28 entry copy; +0x2e label text; +0x22e flags; +0x230.. Bezier floats; +0x248/+0x24a drawn position; +0x24c window descriptor (0x78 bytes, window list `0x224fc`). Last used target kept in `0x241f4`/`0x241f6`.
- `deck_tutorial_start_card_move` refusal codes (shown with message kind 2 through table `0x21a6c`): 2 no target, 4 three same-name copies, 5 forbidden, 6 limited, 7 semi-limited, 8 owner-recipe card (with the card id in the high half), 9 out of memory.
- Message window `0x241f8` (text `0x24318`, 0x800 bytes) kinds: 2 move refusal, 3 deck check passed (strings 0x21/0x22 with/without key card), 4 deck check error (table `0x21a80`), 5 limit error, 6 filter result count, 7 an indexed message (strings 0xb1, 0xc3 + n). The buttons come from the button style, low nibble of window `+0xca` (kind 3: style 2; kind 7: style 3; `../ui.md`); `+0xd4` is the cancel item of `ui_update_list_window` (used with `+0xc8` bit 5), not a button count. While a message is open its kind sits in bits 7-14 of `0x22560` and the editor only runs `deck_tutorial_update_deck_message`.
- Sort menu record `0x24b24` (0x18 bytes), filter record `0x241ec`, search record `0x24b28` (0x60 bytes) follow rel_deck's layouts.

## Packs 07-10: text search, drawing, message window

- Opcode 0x13 (`caption` in docs/formats/deck.md) copies its strTbl string into the query of the open text search (`deck_tutorial_set_search_query`, search record `0x24b28` +6) and does nothing when no search is open. `deck_tutorial_update_text_search_menu` has no branch that opens text entry on the query box (rel_deck's update opens the on-screen keyboard there), so in the tutorial the query comes only from the script or the search history. Suggested opcode name: `set_search_text` (high for the behaviour).
- The script message window is a copy of rel_field's field message window (`ui_field_*` functions, block `0x24b2c`, 0x180 bytes; descriptor `0x24b80`; window list `0x24b34`; three line records at `0x24c20`). ## Module summary (for docs/subsystems/deck.md)

`rel_decktutorial` (library module 0x12, `libdeck_tutorial_rel`) is a self-contained copy of the deck editor driven by a bytecode script. Start: `deck_tutorial_start(script, heap_args)` sets up memory, saves the card flags and trunk option it may change, and sorts its two resource tables. Update: `deck_tutorial_update` loads `deck/tutorial.ehp` and `deck/all_<l>.ehp` and opens the card-image reader (state 0), fades in (1), runs the script interpreter and the editor every frame (2; START opens a quit dialog), fades out (3) and shuts down, restoring the save fields (4), returning 1 when done. Draw: `deck_tutorial_draw`. The editor reads only the masked input `0x22c48`, which the interpreter fills from the pad filtered by `allow_buttons`, or injects itself during `wait_button` demonstrations. The editor's lists start from the sample-deck table `0x212ac` filtered by the script number, not from the player's save.
