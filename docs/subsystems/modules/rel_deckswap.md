## Purpose and flow
Library `libdeck_swap_rel` (id 0x0a). Between the games of a match the player moves cards between the main/extra deck and the side deck ("side decking"). It is a cut-down copy of the `rel_deck` editor UI: three lists instead of six (no trunk, no card-list pool), the same pane/layout system, sort, filter, text search, command menu, card viewer and undo. All addresses below are module offsets.

- `deck_swap_start(deck, card_list_count, card_list_states, own_heap)` (`0x00000008`): `deck` is a 0xc0-byte deck struct (counts +0/+4/+8, ids +0xc/+0x84/+0xa2, `docs/formats/deck.md`), the other two describe the save card list (count, u16 state per item: 0 free, 1 main, 2 side, 3 extra). With `own_heap == 1` it creates its own 0x44e000-byte FPL and opens a cardh.cip reader; otherwise it borrows 0x3af000 bytes of the duel-draw heap and the large card-art reader (the in-duel case).
- `deck_swap_update` (`0x000001dc`) state word `0x00018cd4`: 0 load (card reader + resource files), 1 browse, 2 card move, 3 command menu, 4 sort menu, 5 filter menu, 6 text search, 7 hold-L, 8 hold-R, 9 fade out, 10 release (returns true when done). `deck_swap_handle_input` dispatches; `deck_swap_tick` runs every frame.
- `deck_swap_draw` (`0x0000cc7c`) draws background EHFs, panes, card info, overlays; OSK backdrop capture as in `rel_deck`.
- Leaving: Cancel opens message 2 (two-choice, dictionary word 0xf) only when the main, extra and side totals equal the deck struct's counts, otherwise message 3 (word 0xbc): the swap must keep the deck sizes. "Yes" commits (`deck_swap_commit_lists`): lists written back to the deck struct (main +0xc, extra +0xa2, side +0x84), card-list item states 1/3/2 re-assigned, edit block and layout saved.
- Network duels: a 0x1518-frame (90 s at 30 fps) limit `0x00018fb4` is armed when `system_get_net_active_flag()` is set; it is drawn as m:ss (`deck_swap_draw_time_limit`, blinking below 300 frames). At 0 message 5 (word 0x12) is shown and after 0x2e frames the screen commits without writing the deck (`deck_swap_commit_lists(0)`) and closes: the previous deck is kept.

## Key structures
- Lists `0x00018cdc + 0x20 x k` (k = 0 main, 1 extra, 2 side), same layout as `rel_deck`: +0 kind, +4 6-byte entries, +8 count, +0xc total copies, +0x10 view array, +0x14 view count, +0x16 sort mode (bits 0-3), order (4-5), filter (6-9), +0x18..+0x1d saved cursor. Builders in the table `0x0001837c`, capacities u16 at `0x00018388`.
- Entry flags: byte 4 bits 0-6 copies, bit 7 card-list item; byte 5 bit 0 looked-at (set after 16 frames under the cursor), bit 5 key card (`deck_slot_key_list_contains(1, id)`).
- Mode byte `0x00018fe0` (= `rel_deck` 0x08ebf1a0): bits 0-3 layout 0-7, bits 4-5 active pane, bit 6 OSK backdrop/input block, bits 7-14 open message type. Pane records `0x00019020` (pane 0) and `0x0001904c` (pane 1), 0x2c bytes each, same fields as `rel_deck`.
- Pane assignment: pane 0 shows list 0 or 1 (or 0-2 in single-pane layouts), pane 1 always shows list 2 (`deck_swap_cycle_pane_list`).
- Card move record (`0x00019fe4`, 0x34 bytes): see `deck_swap_start_card_move`. Target rule: from side, frames 3 and 10 (hypothesis: Fusion and Synchro) go to extra, everything else to main; from main or extra the card goes to side. Undo stack: 8 records of 10 bytes at `0x00018f4c`, count `0x00018f4a`.
- Records of the menus: filter `0x00019fc8` (0x18), command `0x00019fe0` (0x18), sort `0x00019ff4` (0x18), text search `0x00019ff8` (0x60), message window `0x000196a4` (0x120 + text 0x800 at `0x000197c4`), OSK block `0x00019ffc`.
- Frame-category counters: 7 x u16 at `0x00018f3c` (main + extra entries).

## Files and resources
- Resource system copied from `rel_deck`/`rel_shop`: `deck_swap_get_resource(id)` binary-searches the 12-byte records of `0x0001891c` (0x29 ids with bit 0x8000) and `0x00018b30` (2 ids with bit 0x1000): u16 id, u16 file group, cached member pointer, member-name format (`%c` language letter from "jegfis"; ids 0x8036-0x8037 use a fixed letter). Files: 2-record table `0x00018664` (u16 group, pointer, path format), loaded from container root 3 (`deck/deckswap.ehp` per the module catalogue; the path strings themselves were not printed in the packs).
- Resources used: 0x8001/0x8002/0x8032 thumbnails and art variants, 0x8006 window parts, 0x8007 icons, 0x8009 digits, 0x800a/0x800b/0x800c icon sheets, 0x8010/0x8011/0x8024 card view, 0x8012/0x8015 card viewer, 0x8013 button help panel, 0x8021 background EHF, 0x8022 tab EHF, 0x8031 card thumbnail index table (u16 sorted list), 0x8033 dictionary (all UI words), 0x1010/0x1011 count indicator EHFs.

## Corrections / notes for docs
- The module catalogue says `rel_deckswap` is loaded by `rel_duel_mgr` and `rel_labo`; the packs show only `rel_labo` (`FUN_00000034`) as an import-stub caller of start/update; `deck_swap_draw` has an import stub without callers.
- Many small "twin" lines are false matches because callees are masked: `0x00004f8c` is `deck_filter_by_attribute` (not `_by_race`), `0x0000c24c`/`0x0000c2a0` are `ui_close_/ui_release_search_filter_windows`, `0x0000f850`/`0x0000f8bc`/`0x0000fa00` are `ui_draw_spell_trap_icon`/`ui_draw_attribute_icon`/`ui_draw_group_header_icon_c`.
- Repeated static copies of BOOT pixel wrappers got numeric suffixes for uniqueness: `ui_list_window_draw_text_2..4`, `ui_draw_level_badge_text_fit_2..4`, `ui_window_draw_text_px_2`, `ui_draw_table_icon_a_2`.
