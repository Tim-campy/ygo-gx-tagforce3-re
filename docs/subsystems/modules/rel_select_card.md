## Purpose and flow

`rel_select_card` (`libselect_card_rel`, module id 0x1d) is a two-list card picker built from a copy of the deck editor's UI set (`rel_deck`). It is a library module: callers drive it through the exports `ui_select_card_open(mode, resources, &count, ids)`, `ui_select_card_update()` (returns true when finished), `ui_select_card_0787468b` (better name `ui_select_card_request_exit`: sets the exit flag 0x000199ac and forces state 10) and `ui_select_card_close()` (frees the reader buffer and the archives the module loaded itself).

- **Modes** (`0x00019700`, the first argument of the open call):
  - 0, story (`rel_story` `world_state_start_select_card` passes `(0, 0, 0, 0)`): list 0 = every valid card with save card flag bit 0 (owned cards, `save_test_card_flag_bit0`), list 1 = the save "card list" (`save_get_card_list_*`). Only list-0 entries whose byte 5 bits 2-4 equal 4 can move; list 1 is limited to `deck_select_card_get_card_list_capacity()` = (save state `+0xfdf4` - 1) / 2 + 1, at most 99. On confirm the save card list is rewritten (count, ids, states from byte 5 bits 2-4). The 99-entry save card list documented in `save.md` is therefore edited here (answers part of the open question about that list: it is a player-chosen list of up to 99 cards, picked from the owned cards; the meaning of the per-item state 1-4 is still open).
  - 1 (`rel_conv_machine` and `rel_labo`): list 1 = the caller's ids merged into entries with copies (capacity 99 copies, limit 0x62 checked before a move), list 0 = every card with free copies (`deck_count_free_card_copies_2`). On confirm every copy of list 1 is written as one u16 id to the caller's array and the count to `*count`; the "new" state of chosen cards is cleared.
  - 2 (wireless card trade, `rel_title` `ui_card_trade_open_card_select`): list 1 = the caller's ids one per entry (at most 5), list 0 = free copies minus the ids already offered (`deck_count_free_card_copies`). Same output as mode 1.
- **Heap.** `resources[0]` is the caller's heap; without one the module creates an FPL of 0x600000 bytes (0x800000 in mode 2) and a heap on it, and deletes it in `deck_select_card_shutdown`.
- **States** (`0x00019704`): 0 loading (`deck_select_card_load_resources`), then fade-in (mode 0 also plays track 4); 1 browse, 2 card move, 3 command menu, 4 sort menu, 5 filter menu, 6 text search, 7 hold-L scroll, 8 hold-R tools, 9 fade-out after confirm, 10 shutdown. A message window (kind in bits 7-14 of `0x00019aa0`) suspends the dispatch: kind 2 rule message (u16 table 0x00018d1c), 3 leave question (answer 1 commits and fades out), 4 filter or search result count.
- **Input.** Same button map as the deck editor (`docs/subsystems/deck.md`): d-pad cursor, hold L scroll/page/group jump, hold R tools (confirm transfer, cancel toggles the save byte-1 flag, Square sort, Triangle filter, Select undo), Triangle command menu, Square cycles the list shown in a single-pane layout, Select switches grid/list layout, cancel asks to leave.

## Key structures

- **Lists**: two 0x20-byte records at `0x0001970c` (list 0) and `0x0001972c` (list 1), the `rel_deck` editor-list layout: `+0` index, `+4` entries (6 bytes: id, image index from `fileTbl.dat` resource 0x8031, copies bits 0-6 of byte 4, byte 4 bit 7, byte 5 bit 0 seen, bits 2-4 card-list state), `+8` count, `+0xc` total copies, `+0x10` view array, `+0x14` view count, `+0x16` sort mode bits 0-3, order bits 4-5, filter bits 6-9 (8 = text search), `+0x18`-`+0x1d` saved scroll and cursor.
- **Panes**: two 0x2c-byte records at `0x00019ae0` (pane 0, list 0) and `0x00019b0c` (pane 1, list 1): `+0` list pointer, `+4` bit 0 list layout, `+6` first visible, `+8` column, `+0xa` row, `+0xc` 0x1e-byte geometry copied from 0x00018e10 (layout table 0x00018ea8, 8 bytes per layout 0-7).
- `0x00019aa0`: low nibble layout, bits 4-5 active pane, bit 6 keyboard active, bits 7-14 message kind.
- Undo: 8 x 10-byte records at `0x0001994e`, count `0x0001994c`.
- Move record (0x34 bytes, `*0x0001aaa0`), filter record (0x18, `*0x0001aa84`), sort record (0x18, `*0x0001aab8`), command record (0x18, `*0x0001aa9c`), search record (0x60, `*0x000196f0`): same layouts as their `rel_deck` counterparts (see the rows).
- Edit block copy at `0x0001974c` (0x200 bytes, `save_read_edit_block`/`save_write_edit_block`); its first 8 x 0x40 bytes are the text-search history. The layout is stored with `save_set_setting_b1_bits0_2`, the trunk option with `save_set_setting_b0_bits6_7`, both shared with the deck editor.

## Files and resources

- Resource ids resolve through `deck_select_card_get_resource` (the rel_deck scheme, `docs/subsystems/ui.md`): 0x29 records at `0x00019338` (ids 0x8xxx) and one record each for 0x1010, 0x2010, 0x4010 (the per-mode EHF backdrop, played with `ui_ehf_set_play_range` by layout), 12 bytes each `{u16 id, u16 archive id, cached pointer, member-name format}`. Member names and archive paths are `sprintf` formats with the language letter from `"jegfis"`; ids 0x8036/0x8037 use a fixed letter.
- Four archive records at `0x00019068` (12 bytes: `{u16 id, pointer, path format}`), loaded from root 3 (`USRDIR/`) with `container_load_file`: archive 1 (common UI set, also accepted from the caller as `resources[2]`) and one per mode (2, 3, 4; or `resources[3]`). The module catalogue names `labo/rental.ehp` and `labo/conv_machine.ehp`; which record is which file was not read here.
- Card images through a `cardh` CIP reader (`card_db_open_cardh_cip`, 0x135000-byte buffer) unless the caller passes one (`resources[1]`).

## Relation to rel_deck and rel_shop

About 60 functions are byte-identical copies of `rel_deck` (text search, filter, panes, cursors, command submenus, Horspool search) and four of `rel_shop` (sort menu window helpers). Copies whose twin line was a false positive (masked local callees): `0x0000110c` (is `ui_close_search_filter_windows`), `0x00001160` (`ui_release_search_filter_windows`), `0x00004a0c` (draws the message window, not a sort menu), `0x00006b70` (attribute filter, not race). Three copies of the BOOT pixel wrappers exist twice in this module (`0x000017f4`/`0x00005de0`, `0x000012a8`/`0x00005e00`/`0x00009b74`) and `ui_draw_table_icon_a` twice (`0x000061c4`/`0x0000cfcc`); the second copies got module names.

## Open questions

- `deck_select_card_draw_card_row_detailed` and `_compact` call `save_get_card_state` with `card id == 1` (`xori v0, v0, 1; sltiu a0, v0, 1`), not with the id, and pass the result as `is_new` to `shop_draw_card_badges`. The machine code is unambiguous; whether it is an original bug is open (hypothesis, medium). The `rel_deck` and `rel_shop` twins were not compared; check the badge in PPSSPP before copying this into the port.
- Which of the four archive records is `labo/rental.ehp`, `labo/conv_machine.ehp` and the common set (read the path formats at 0x00019068 from the binary).
- Meaning of save state `+0xfdf4` (the mode-0 card-list capacity grows with it).
- Meaning of the card-list item states 1-4 (byte 5 bits 2-4; only state 4 can be moved in mode 0).
- `ui_select_card_ae4aa6ec` (export at `0x0000e89c`) draws the same frame as `ui_select_card_draw` but returns the display list and a "drawn" flag through its argument; suggested name `ui_select_card_draw_to_list` (M). No module calls it.
