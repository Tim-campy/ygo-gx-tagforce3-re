# Effect helpers: predicates, getters and shared queries (work package 4)

This round names the most widely reached **unnamed helpers** of the per-card effect handlers in `gmodule/rel_duel_eng.prx` (runtime base `0x09be1400`) and the `BOOT.BIN` functions they import (image base `0x08804000`; the module calls them through `thunk_` stubs at `0x09de4…`, e.g. `0x09de4a24` → `BOOT 0x0885fef0`). The worklist was `tools/effect_classify.py`'s `worklist.csv` (`effect-classification.md`), taking the top rows whose name was still `FUN_`/`thunk_FUN_`.

Result: **169 names** (79 in `rel_duel_eng`, 90 in `BOOT.BIN`) and **140 signatures** (57 + 83). Names are in `re/names-duel_eng.csv` and `re/names.csv`, signatures in `re/documented-duel_eng.tsv` and `re/documented.tsv`. Every address was checked to start a function in the Ghidra project (`FuncAt.java`, read-only copy).

Basis for every row: Ghidra decompilation of the function (read-only copy of the project), its callers, and the card ids it compares, resolved to card names with `tools/cardinfo.py` on the maintainer's own `cardinfo_eng.ehp` (card kinds and races from `docs/formats/cardinfo.md`). Nothing here was traced in PPSSPP. Confidence per row: H (high), M (medium), L (low). "Records" is the number of effect-table records whose depth-3 closure reaches the function, and "(resolve)" the number reached from the resolve slot; for `BOOT.BIN` functions it is the count of the import stub, "—" when the function is not reached through a stub.

Conventions: `side` is 0/1; `slot` 0–4 monster zones, 5–9 spell/trap zones, 10 field zone, 11 the player slot; a *reference* is `side | slot << 8`; slot fields are those of `duel_core.md` (`+0x00` card id, `+0x06` position, `+0x08` face-up, `+0x0a` marker list, `+0x0c` value word, `+0x10` flags). "Unflagged" means flag bit 3 clear (the bit that disables effect handlers); several helpers also require flag bit 2 clear for an "active" source, whose meaning is still open.

## Findings

1. **The archetype predicates are a table (H).** `card_db_is_in_archetype(id, n)` (`BOOT 0x088633f8`) calls entry `n` of a 63-entry function table at `0x0889e2d8`; every entry is a fixed compare chain of card ids (no card-data field is read). Entry 8 is Elemental Hero, which matches E - Emergency Call passing 8 to `duel_effects_candidate_in_archetype` (`effect-helpers-deck.md`). The index list is below; the port can replace the 63 functions with 63 id sets. Two entries remain unnamed: 60 (`0x08862fec`) tests ids `0x1f08`–`0x1f0b` and `0x1f21`, which are absent from the English card database.
2. **Card-kind predicates (H).** `card_db_get_kind` returns the stored kind halved (`card_db.md`): 0 normal, 1 effect, 2/3 fusion, 4/5 ritual, 6 toon, 7 spirit, 8 union, 9 gemini, 10 token, 11 god, 13 spell, 14 trap, 15/16 tuner, 17/18 synchro. The imported helpers test exactly these values: `card_db_is_monster` (not 13/14, id non-zero), `card_db_is_effect_monster` (1, 3, 5–9, 11, 16, 18), `card_db_is_toon/spirit/union/gemini` (6–9), `card_db_is_tuner` (15, 16), `card_db_is_normal_monster` (0, 15). `card_db_get_frame` maps the kind to a frame class (fusion 3, ritual 2, synchro 10, gods 4–6, spell 7, trap 8, token 9), and `card_db_is_fusion/ritual/synchro` compare it.
3. **Name aliases (H).** `card_db_is_same_name(a, b)` is the "same card name" rule: it unifies token variants, the Neo-Spacian Moss and Dolphin pairs, Umi with A Legendary Ocean, Harpie Lady with Harpie Lady 1–3 and Cyber Harpie Lady, and alternative-artwork ids. On the field it is used through `duel_core_is_slot_card_named`; in the graveyard through `duel_core_is_graveyard_card_named`, which also applies The Lady in Wight → Skull Servant and Harpie Queen → Harpie Lady.
4. **Zone locks (H).** `duel_core_is_zone_usable` is the single test behind every "free zone" query: the zone-locking cards (Phantom Dragon, Ojama King/Knight, Ground Collapse, Fog Palace, Intoxicated Bug, Mystical Cards of Light, Seismic Shockwave) leave kind-6 records on the player slot whose value word is a zone bit mask (`zone + 16 × side`). The free-zone counters and finders (`duel_core_count_free_*`, `duel_core_find_free_*`) all go through it; the finders use preference tables at `0x09deba0c` (monster) and `0x09deba20` (spell/trap).
5. **Special Summon permission (H).** `duel_core_can_special_summon_card_to` is the full check used by the candidate scanners: Light of Intervention, Set restrictions (Searchlightman, Dark Simorgh), `card_db_can_be_special_summoned`, the Nomi list (`card_db_is_special_summon_only`), per-card summon conditions, then the card-independent restrictions `duel_core_can_summon_card_from` (Barrier Statues and Tualatin through `duel_core_can_summon_attribute`, Deck Lockdown, Chain Energy, Cold Wave, Queen of Thorns, Power Filter, the CPU veto) and, face-up, Rivalry of Warlords / Gozen Match.
6. **Correction.** `summon.md` described `0x09c0c458` as "Special Summon allowed (`duel_core_can_special_summon`)". The function tests duel mode 7, Mask of Restrict and Fog King, i.e. whether **Tributes** are allowed; it is named `duel_core_is_tribute_allowed` (the registry's `duel_core_can_special_summon` is `0x09c0c4bc`). This is consistent with its callers (`duel_core_can_tribute`, `duel_core_count_tribute_value`, the ritual condition).
7. **Link targets (H).** `duel_effects_add_link_target` is the common "record a chosen target" routine of the target-choice handlers: it stores the packed target in the chain link (`chain.md` layout), increments the target count `+0x06` and posts command `0x28` with the target number, so command `0x28` is the target marker as well as the reveal command (`effect-helpers-deck.md`); with `c = 0xffff` it carries targets beyond the fifth. `duel_effects_record_link_slot` stores a slot in the same list without counting it as a target.
8. **Selection mode 9 (H).** `duel_core_begin_select_target` and `_ex` are the two openers of input mode 9 listed in `summon.md`: a field-card selection with a filter callback; the CPU path goes to the AI wrapper `0x09d9ea94`.
9. **Link-duel transport (M).** `duel_core_net_send_command` / `duel_core_net_send_packet` build and send the wireless-duel messages (debug strings "Iam%d SEND", "OWNERto%d", "RIVALto%d", "CAST"); `duel_core_run_pending_action` is one of 22 callers.
10. **Classifier effect.** With these names in a temporary copy of the registry the classifier's resolve coverage stays at 96.1 % (the new names are `stop` leaves, as intended), the number of unnamed callees reached drops from 507 to 363, and some categories become more precise: `duel_core_add_deck_card_to_hand_ex` is now an `add_to_hand` leaf, so searches no longer leak `mill` (172 → 95 records), `move_list_card` (103 → 22) and `timing_event` (121 → 40) from its internals; `add_to_hand` rises from 131 to 190. Names reach `re/functions.csv` only after the maintainer re-exports the registry from Ghidra.

Not named in this round (left for the AI agent or for later): the AI wrappers and deciders in the worklist (`0x09d9ea94`, `0x09d9f0c0`, `0x09d99284`, `0x09d990a4`, `0x09d67474`, `0x09d9f654`, `0x09d9a4b4`, `0x09d9a1fc`, `0x09d9dc18`, and the AI chain classifier `0x09bf3c34`), the pending-action poster `0x09c0f55c` (mode 9 of the card request, meaning unconfirmed), and the small single-card helpers `0x09c54658`, `0x09c2d75c`, `0x09c502c0`, `0x09c50dc4`, `0x09c623c0`.
